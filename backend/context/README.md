# 统一上下文与混合检索

`ContextService.collect(ContextRequest)` 是认知、表达、Harness 初始上下文和内部检索工具的共同入口。
调用者必须使用服务端绑定的角色及频道，不能从模型生成的参数中接受身份或权限。

## 事实与索引

- 业务库的 `context_sources`、`context_grants`、`context_tombstones` 是来源与权限事实；
  `context_references` 保存会话中的明确引用，`context_jobs` 记录索引状态。
- `retrieval.db` 只保存派生片段、FTS5 和向量，可以重建。检索先建立当前可见来源表，再进行词法、向量排名及 RRF 合并。
- `read_file`、`read_document` 的实际成功返回立即登记；任务最终失败仍保留成功读取的片段。
  PDF/OCR 页码与置信度、DOCX 段落/表格、XLSX 工作表/行、文本游标和原始哈希随来源保存。
- 旧调用仅剩元数据时只登记“成功读取、正文未保留”，不恢复或编造正文。
  回填不读取 Hermes 诊断日志，不扫描授权工作区。
- Wiki 只从现有缓存回填，保留 URL、抓取时间、原始过期标记。原作资料不自动成为已核实关系或本人的执行经历。
  抓取时间未知或超过七天时标为旧缓存；查询不会为刷新缓存自动联网。

## 连续性与权限

完整文件名（可带空格）、已确认的会话引用、角色可见读取证据依次参与指代解析。
同名不同路径、多文件未确认时返回澄清候选；不因为文本相似就替换明确限定的文件。
读取证据与已验收任务结果分别表达；`ownRead` 和 `readerId` 区分本人读取和同伴分享。

私聊可以回忆本人的旧经历；群聊只使用当前频道的证据或明确分享的片段。
成员资格、加入时间、遗忘和纠正状态每次都从业务库核对，没有跨角色/频道的结果缓存。
回复发布前再次检查使用来源的权限及版本；失效的待投递回复不会重发。
分享撤销立即使 grant 失效，遗忘标记在重建时仍然生效；无有效证据的索引由后台清理。
清理记忆和系统重置同样涵盖新来源表、引用和索引。

## 模型与运行

默认使用 FastEmbed CPU 的 `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2`，384 维。
固定模型仓库修订与各文件 SHA256 见 `embedding.py`。
应用不会在查询时自动下载模型或自动切换云端；缺失时显示词法降级状态。
在设置中下载固定版本，或选择通过相同哈希校验的本机目录。

每块最多 96 个 tokenizer token、重叠 16 个；模型安装前采用保守 Unicode 分块，安装后重建。
后台单循环以 16 块为一批，ONNX 最多两个 CPU 线程；在前台任务期间让出。
词法与向量各召回 30 项，精确实体优先，随后来源去重、合并相邻片段、预算打包。
低置信度纯语义命中作为澄清候选，不自动当作回答证据。

可选云端 `/embeddings` 使用独立配置和受保护密钥。切换接口、模型、版本或维度会隔离向量缓存。
选择云端会把登记的资料片段发送到用户配置的服务，不复用聊天接口凭据。

全文索引由用户明确发起，通过 `index_document` 逐页调用原有授权读取能力。
它不扩大目录授权，也不把未读取的文件变成角色知识。

## 消耗与诊断

复用 `dialoguePreset`，上下文软目标为 compact 4K、balanced 8K、rich 12K。
最终组装会先省略低相关历史，再允许必要指令、当前问题和证据超过软目标；模型硬上限包含输出预留。
多阶段总输入须合计各次调用，不能把上下文目标当成整个回合的账单上限。
明确详细请求保留必需答案。

省流模式的普通聊天使用精简的结构化理解/决策协议，再表达。
检测到工具、邀请、目标或承诺相关需求，或模型明确要求回退时，执行完整认知链。
群聊沿用已有决策，补充观点、未答请求和回应对象；词面指标仅用于识别纯复述附和，不直接结束话题。
次数上限只是防循环保障，有未答请求时记录为等待状态。

可选本地聊天 tokenizer 仅在配置的模型名匹配时使用，并注明未计服务商协议开销。
否则输入量明确标为估算；`actualUsage` 仅取自服务商返回，缺失是 `null`。
`context_traces` 保存来源、选择/省略原因、调用输入量及实际用量，不保存隐藏推理。

## 验证

专项：`.venv/Scripts/python.exe -m pytest tests/context -q`

真实 ONNX 60 条中英文检索验收：设置 `AZURJUUS_CONTEXT_TEST_MODEL` 为已校验的模型目录，
运行 `tests/context/test_retrieval_acceptance.py`。未设置时只跳过这个需要模型资源的测试。

`test_budget_replay.py` 用相同 30 条固定输入回放三档，走生产组装与认知代码、使用受控模型，
测量提交输入估算值、调用次数与重试。它不证明实际计费节省或角色自然度。

`tools/context_live_acceptance.py` 在隔离业务库和合成 PDF 上使用已保存的模型凭据，
验证真实 Harness 阅读、闲聊恢复准确文件编号、来源展示及省流调用；不改原会话。
`tools/context_ui_acceptance.py` 在隔离应用上用真实浏览器验证设置与重建操作。
报告保存在 `validation/`。角色自然度及三档真实模型长期成本仍需真实回放和盲评。

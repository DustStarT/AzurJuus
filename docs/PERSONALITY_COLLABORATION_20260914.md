# 人物表达与协作更新

日期：2026-09-14。

## 本轮变更

| 用户问题 | 实现 |
| --- | --- |
| 私聊出现秘书 | 回传改为系统任务通知；旧外来角色消息显示为中性通知；私聊模型历史排除其他人物发言，避免身份污染 |
| 说话太像模板 | 新增共享表达规则，要求通过关注点与行动体现人设，不复述性格标签，不固定汇报格式；任务证据与聊天表达分开 |
| 成员只能顺序等待 | 新增任务内 discuss 通信；独立单并发讨论通道，不阻塞两个工作名额；意见持久化并送入后续工具结果与最终复核 |
| 气泡过长 | 角色用空行选择说话节奏；前端按空行形成独立气泡，超长段落按句子兜底；保持稳定节点与分段边界 |
| 缺少负面性格与纠错 | 允许有动机的拖延、嫌麻烦、疏忽判断和过度谨慎，由同伴提出具体反对意见；不随机注入磁盘破坏或伪造证据 |
| 协作群不能删除 | 群聊头部新增删除入口；停止未完成任务、归档任务及群聊，保留文件与审计数据；保护默认港区频道 |
| 调度与效率 | 依赖满足立即补入空闲执行位；取消整批等待；旧快照晚返回时不覆盖新数据；讨论有八次预算及单次超时 |
| 技能交互与学习 | 成员资料新增“方法与成长”，查看可用方法、候选、使用记录和源任务；讨论不作为已验证工作成果计分 |
| 朋友圈人格与经历 | 动态和评论接入相同表达原则；验收通过后，参与者的成果摘要写入近期记忆供社交参考；保留任务抢占机制 |
| 中文教学文档 | 新增 CODE_WALKTHROUGH.md，按请求、函数、状态、证据、并发、存储、人格与界面逐层解释 |

真实讨论中，能代提出减少检查，信浓解释来源不能省略；后续消息确认来源核对，并提醒不要修改上一轮无关文件。讨论记录包含成员、内容、回复与已消费阶段。它证明这条讨论路径能工作，不代表人物长期行为已达到原作效果。

## 目前仍然有限的地方

1. 人物差异仍依赖人设质量与模型推理，尚无长期情绪状态、稳定行为评分或完整人格评测集。
2. 讨论可以提出修正，但不能自由增加成员或自动改写依赖图；工作产物的改变仍要经过真实工具。
3. 学习候选默认禁用；独立试用、效果比较、成熟晋升和公有方法版本治理仍待实现。
4. 朋友圈能按关系生成互动并避让工作，但任务经历驱动的长期社交变化仍不完整。
5. 尚未做所有硬件、系统缩放与长时间会话组合的性能验收，不能把一次无闪烁记录说成全局帧率保证。

测试全部使用独立数据库和合成工作区，没有删改用户群聊或发送用户工作区文件。

## 本轮用户问题

### 查询有结果却失败，消息消失

实际记录存在两种情况：

1. `list_dir` 与 `deliver` 都成功，但模型把“未读 PDF 正文”写入 `unresolved`。用户只要求列目录；旧调度器在审查前直接认定成员失败。
2. 真实 DeepSeek 重复验收中，模型成功查询并回答，却没有调用 `deliver`。

现将带未解决说明的有效提交置为 `submitted`，允许进入秘书只读复核。审查按用户原始范围决定接受或修订，不能以可选深入分析扩大验收条件。文字型查询允许空产物数组；仍然必须引用实际成功工具调用。

漏交时在同一个 Hermes 会话补交，最多两次。补交的工具网关只开放只读核验和交付，防止重复写入、命令或网页提交。预算用尽暂停，没有有效交付仍不标记完成。

每个执行阶段的实际回复在完成事件到达时持久化，早于任务验收；验收失败不删除已有回复。旧失败任务不根据文字内容自动改成成功。

### 流式结束闪烁

过去将流式消息与持久化消息分别渲染，结束时先删流式项、等待刷新后插入正式消息。现在二者共用 `messageId` 和同一个 Vue 列表节点；只有数据库快照包含相同 ID 和正文时才移除临时缓存。WebSocket 新事件也不会被较旧的运行快照删除。

`tools/ui_message_acceptance.py` 在隔离数据库中逐帧检查节点连续性，涵盖 60 段流式事件、消息持久化、最终刷新、中文组合输入、焦点及选区。证据见 `validation/ui-messages/report.json`。

### 工作记录删除与清空

工作抽屉新增“删除记录”和“清空已结束记录”。清空遍历全部记录，不限最近 200 条；保留正在执行和暂停待继续的任务。单独删除暂停任务会先取消，正在执行或退出清理中的任务需要先停止。

这属于记录归档：聊天消息、实际文件、工具证据和幂等标识保留，记录不再进入任务列表或重启恢复。避免清空列表后相同请求被重复执行。删除事件通过 WebSocket 同步；有 API 和真实按钮回归。

# AzurJuus 技术报告：当前实现与边界

更新：2026-09-17。本文可作为报告底稿，个人贡献请按实际参与填写。实现细节见 [代码讲解](CODE_WALKTHROUGH.md)，口头表述见 [面试讲解](INTERVIEW_GUIDE.md)。

## 一、问题与目标

项目结合本地执行与角色通讯，主要解决：模型说完成却没有产物，多成员协作状态不连续，执行提示直接进入聊天造成机械表达。对应设计是证据驱动验收、持久化调度与认知、执行和表达分离。

## 二、架构

Vue 提供界面，PySide6 承载桌面窗口，FastAPI 提供本地服务。AzurJuus 调度任务，Hermes 以受管理进程承担模型工具循环，权限网关执行实际操作。默认 SQLite，不要求 Docker 或独立数据库服务。

闲聊直接使用无工具表达服务；任务经过工具与验收后再生成角色短消息。协作使用有依赖子任务与定向讨论，最多两个执行成员并行。共享写入和桌面仍有资源约束，模型并行不等于副作用任意并行。

## 三、关键机制

| 机制 | 实现 | 边界 |
| --- | --- | --- |
| 执行可靠性 | 调用记录、审批、结构化交付、复核 | 不保证开放式内容永远正确 |
| 恢复 | 持久化状态、事件、请求编号、未知副作用核验 | 任意外部操作不一定可撤销 |
| 事件一致性 | 源事件、消费游标、幂等收件、短事务 | 不是跨库全局事务 |
| 人格连续性 | 基础卡、可见经历、定向关系、版本检查 | 不是完整人类心智模拟 |
| 表达隔离 | 无工具模型、事实包、对象、短消息校验 | 细微失真仍需评测 |
| 投递恢复 | 稳定编号、待投递正文、幂等写入 | 允许暂时不同步后补齐 |
| 技能成长 | 来源候选、三个隔离场景、基线比较、回退 | 有限任务族，不训练权重 |
| UI 稳定性 | 组件局部更新、本人标识、气泡队列 | 性能需要实测 |

## 四、取舍与规模管理

复用 Hermes 减少重复开发，但增加版本与协议兼容成本。独立表达改善上下文边界，但增加任务发言的调用和等待。SQLite 简化部署，业务与运行库分离则需要恢复与幂等策略。

本轮继续移除服务层无调用者的旧模拟执行、任务推进和手工工具路径；旧流程展示抽成只读函数，历史数据结构保留。后端必需，Docker 在可选部署目录。目录判断见 [项目组成](PROJECT_COMPONENTS.md)。

复杂度应按自有模块职责衡量，不能把 vendor、node_modules、虚拟环境及构建产物算成自主实现规模；测试和验收脚本也应与产品代码分开。

## 五、验证口径

程序测试检查状态、权限、恢复和事件；真实模型测试检查接入与生成；浏览器和桌面检查布局、输入、退出和性能；人工对照评价自然度。四者分别报告，不互相替代。

本轮结果见 [修复记录](UI_COLLAB_CLEANUP_20260917.md)。此前完整入口测试见 [终端验收](TERMINAL_ACCEPTANCE_20260917.md)，不能将历史验收写成每次修改都重新通过。

## 六、限制与下一步

尚未完成规定的双人自然度盲评，不能宣称达到 65% 胜出率。关系的行为影响受资料与模型制约；技能试用范围有限；Windows 自动化依赖环境；应用网关不是系统沙箱；长时间资源与帧率还需更多样本。

下一步应优先完善可复现人物评价、任务验收器与模块边界，而不是继续增加没有证据的能力描述。

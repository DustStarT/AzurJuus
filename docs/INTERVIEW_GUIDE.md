# AzurJuus 项目现况与面试讲解

更新：2026-09-17。当前实现见 [代码讲解](CODE_WALKTHROUGH.md)，报告底稿见 [技术报告](TECHNICAL_REPORT.md)，验证见 [本轮记录](UI_COLLAB_CLEANUP_20260917.md)。个人负责范围请按真实参与情况说明。

## 1. 一分钟介绍

AzurJuus 是一个角色化的本地智能体桌面应用。用户可以聊天，也可以要求它处理文件、运行代码或协作完成任务。界面采用游戏聊天终端的形式，但工作的完成与否由实际工具结果和验收流程判断。

系统分成三个关键部分：AzurJuus 负责持久化调度和权限，Hermes 负责模型与工具的执行循环，独立表达服务把允许公开的事实组织成角色短消息。工具日志不用挤进聊天，人物语气也不能改变任务事实。

难点不是接通一次模型接口，而是等待审批、并发协作、断线和重启后仍保持任务状态、消息与人物记忆一致。工程机制已有实现和回归测试；人格自然度仍需人工对照，不能宣称已经解决。

## 2. 技术选型怎样解释

| 部分 | 选择 | 负责的问题 |
| --- | --- | --- |
| 桌面与界面 | PySide6/QWebEngine、Vue 3、TypeScript、Vite | 本地窗口、稳定组件、输入和消息节奏 |
| 本地服务 | FastAPI | API、事件通道、生命周期和配置 |
| 执行核心 | 锁定版本的 Hermes 独立进程 | 多轮模型调用、工具请求与中断 |
| 默认存储 | SQLite | 业务与运行数据，避免桌面依赖数据库服务 |
| 工具 | 权限网关、文档工具、Playwright、Windows 自动化 | 真实操作与可检查结果 |
| 人物层 | 角色版本、世界条目、认知状态、独立表达 | 连续身份、信息边界、关系和说话对象 |

后端运行在本机，不等于必须部署远程服务器。Docker 只用于可选外部服务，默认桌面不需要。模型通常使用云端兼容接口，也保留本地兼容模型入口。

## 3. 用户一句话经过哪里

闲聊：Vue 提交会话和文字；表达服务读取当前角色、可见经历和最近对话，生成完整短消息，校验、保存并投递。它没有本地工具权限，不先运行一次执行模型。

任务：调度器保存运行记录并启动 Hermes；工具请求经过应用网关，检查授权、路径、审批与阶段权限，再执行操作。结构化交付通过证据与产物检查后进入复核，最后表达层根据结果说话。

协作：增加子任务计划和依赖图；最多两个执行成员同时工作，完成一个就重新检查依赖。同伴可以定向讨论，但建议不能直接覆盖别人的任务，调整仍需调度校验。

## 4. 值得深入讲的技术点

### 完成权为什么不能交给模型

模型容易混淆“准备做”“已调用工具”和“结果正确”。项目分别保存工具调用状态、子任务交付证据和整个任务复核结果。等待审批、失败调用或证据缺失时，不能凭一段流畅回复标记完成。

程序能检查文件存在、哈希、退出码、来源调用等，但不能因此证明开放式报告语义完全正确。不同任务仍需合适的验收条件。

### 两个数据库怎样保持一致

业务库保存聊天、人物、技能；运行库保存调用、审批、产物、事件与表达投递。认知以运行事件为源，在业务侧同一短事务内更新状态、消费游标和幂等收件记录。重复读取事件不会重复增加经历。

这是允许重放、幂等消费，不是跨库全局事务，也不是网络恰好投递一次。生成消息先存为待投递；投递失败保留正文和稳定编号，恢复时重投，不重新润色。

### 为什么不能在等待模型时持有写事务

云端等待可能持续几十秒，长写事务会阻塞其他任务和聊天。实现先取快照、结束事务，再等待模型，最后短事务提交。人物反思还检查状态版本，旧结果不能覆盖等待期间的新承诺。

### 五个人物是否意味着五个模型

不是。可以是同一个模型服务，使用不同角色卡、可见信息、关系、方法偏好和对话对象。没有训练五套权重。

关系也不是一个好感分：它是有方向的，区分原作背景、用户设定和实际经历。甲的私人判断不能自动给乙。关系上下文会影响解释多少、如何反驳，但提示影响不是行为保证，仍需评价。

### 为什么独立表达层能缓解机械感

执行提示需要讲权限、证据和交付格式，直接进入聊天就像审计报告。表达层只拿意图、事实包、关系和近期对话，没有工具权限。

任务表达失败只显示异常，不撤销真实成果，也不回退展示原始执行报告。代价是任务发言增加模型调用、等待与事实校验责任。它不能单靠“缩短字数”解决全部自然度问题。

本轮具体修正：协作最终表达原先没有传群聊对象，进入默认面向用户的分支；现在传实际成员和最近公开讨论。原始 Hermes 文字在默认表达开关下已进入工作记录，本轮用测试固定此边界。

### 技能成长到底改变什么

改变外部方法与经验，不改变模型权重。经验证的合作过程形成候选；支持的任务族在独立工作区运行三个场景，与原方法用相同验收器比较。通过才启用个人版本，相关回归可以暂停并回退。没有验收器的任务族保留候选，不称为通用自主学习。

### 气泡为何会偏左，如何证明修好了

跨组件 CSS 选择器编译后没有命中内部容器。仅反转头像行不能保证短气泡靠右。现在组件显式接收“是否本人”，内部布局负责对齐；用实际元素坐标检查长短用户消息右边缘及头像位置，而不只看一张截图。

## 5. 怎样回答项目的不足

- 人格自然度需要匿名人工对照，短消息比例和程序通过率不能替代。
- Windows 自动化受焦点、权限、DPI 和控件影响，不承诺任意专业软件。
- 应用权限网关不是操作系统沙箱，命令不能只靠路径前缀判断安全。
- 未知副作用先核验，不承诺所有外部操作都可撤销或自动重试。
- 帧率采样只代表测试场景，不能承诺所有机器持续 60 帧。
- 历史数据结构仍有维护成本；本轮清理失效执行逻辑，保留历史只读展示。

## 6. 简历和报告的措辞

可以写“实现持久化任务调度、工具权限、可恢复表达投递、角色状态与关系上下文”。不要写“从零实现推理框架”“训练出五个人格模型”“解决通用心智模拟”。

Hermes 是上游执行核心，模型能力来自配置的服务；项目贡献集中在应用整合、交互与可靠性。程序测试、真实云端、桌面检查、人工评价分别列出，测试数量不是覆盖率。

# 聊天终端改造记录（2026-09-17）

后续实测与 UI 复评见 [完整验收记录](TERMINAL_ACCEPTANCE_20260917.md)。真实模型连接已恢复，本文末尾状态已更新；人工自然度评分尚未完成。

本次改变的是“工作结果怎样变成人物消息”，并未替换 Hermes 或降低成果验收要求。程序验证与人格自然度评价是两项不同工作；后者尚未通过验收。

## 一条消息怎样产生

普通闲聊由 `run_coordinator.py` 分流到 `expression.py`，直接调用无工具权限的表达模型，不先运行 Hermes。任务仍由 Hermes 执行；原始说明发布为 `execution.message.*` 事件，在工作抽屉展开查看。任务结果经过原有验收后，再交给表达服务生成短消息。

表达上下文包含终端规则、生效角色卡、人物可见状态、相关背景、近期对话和本次事实包。默认最多三段、180 字，提示目标是 30–120 字；用户明确追问过程时可读取同会话关联工作结果并展开。普通消息不再携带完整执行协议。

表达服务检查来源标识、长度、常见动作旁白，以及事实包未提供的数字和文件名。校验失败最多修订一次；这些规则不是完整语义证明，仍可能漏过隐晦的虚构事实或旁白。技术括号不统一删除。

## 为什么回复失败不等于任务失败

运行数据库新增 `speeches` 投递表，来源事件映射为稳定消息标识，状态经过排队、正文就绪、已投递。正文先保存，再写业务聊天并发布事件。重复来源读取已有正文；已生成正文在投递失败后保持就绪，启动恢复时不重新配音。

表达异常通过 `expression.failed` 和工作记录提示呈现，不把整篇执行报告塞回聊天，也不改写已成功的文件任务。恢复使用相同消息标识；跨数据库并非一个事务，依靠幂等写入避免重复聊天。已完成任务的待投递消息可在启动时恢复，非完成任务仍遵循原调度恢复流程。

每次表达等待默认 15 秒，普通闲聊与任务表达各一个槽位。用量事件保存模型返回的 token 数和耗时；当前没有可靠价格表，因此费用字段为空，不能据此宣称已统计实际费用。

## 人设究竟读哪里

`resources/characters/*.prompt.md` 是导入材料，不是每次聊天直接读取的最终配置。旧账号继续使用数据库人设。`terminal_characters.py` 提供五名角色的新基础卡与六类原创终端示例；人物面板可检查当前版本、差异并应用更新。已记录的用户覆盖优先于基础卡，恢复基础版本是显式操作。

`GET /api/actors/{id}/prompt-preview` 用于本地检查规则、基础背景和实际人设，不返回密钥，不开放给角色工具。完整动态上下文还取决于本次任务、可见经历和对话，不应把预览误认为每一次模型请求的完整副本。

世界书按关键词匹配，最多六条。目前覆盖终端背景、五人阵营身份与部分有出处的关系，尚不是完整港区世界设定。资料区分原作依据与作者表达示例，不默认启用恋爱或誓约语境。同阵营不直接推导亲密关系。

## 界面与消息节奏

按用户复评，角色背景不透明度恢复为 0.19，优先加载同一 Wiki 图片的原文件，失败回退缩略图。侧栏为 92px、按钮为 60px，移除拥挤棋子标志、隐藏装饰节点及对应失效样式。会话卡片减少重描边和阴影，正文统一为 15px。旧任务报告以“历史工作回复”折叠，原文保留。工作抽屉可展开执行原文。

`speechQueue.ts` 按会话串行呈现；`SpeechBubbles.vue` 对新短消息逐段显示，后续间隔依据长度限制在自然档 450–1,000 毫秒。支持即时、自然、舒缓及“立即显示”。长消息直接呈现，切换会话与加载历史不重播；减少动态效果禁用进入动画。后端存储不等待动画。

# 人物认知、关系与方法成长：实现与使用

本文解释本轮新增的生产代码。角色自然度还需要人工评价；“数据能正确流转”和“人物表现自然”是两个不同结论。

## 使用入口

启动程序后，在成员资料中打开“方法与成长”。

- “方法与成长”页显示当前方法、候选、隔离试用状态与证据。候选可能没有适用的验收器，此时不会自动启用。
- “经历与关系”页显示关注事项、记得的承诺、对同伴的看法和来源经历。
- “纠正理解”补充你的解释；“忘记这段经历”排除它及依赖它的后续判断，不删除真实文件或任务审计证据。
- 关闭“使用持续经历与关系”后，该人物不再积累新认知，也不会使用认知上下文。重新打开后不会补记停用期间的事件。
- 清除成长状态保留人设和技能；技能可以单独停用或回滚。主动朋友圈仍由设置中的社交开关管理。

已展示的原始聊天是历史发言，不会因为忘记经历而删除。当前会话仍可能包含这句话；忘记作用于长期认知，不是改写历史。

## 一条消息怎样经过系统

1. HTTP 消息入口建立持久化运行记录，产生带序号的事件。
2. 执行前，认知服务消费增量事件，为实际观察者建立经历；相同事件重放不重复建立。
3. 读取该人物的固定设定、作者行为解释、相关经历、承诺及关系判断。
4. 将这份上下文加入现有 Hermes 请求。普通聊天没有固定增加一次前置模型调用。
5. 模型以角色身份回答，或在任务模式通过原工具网关执行。人格层不掌握额外文件、命令或桌面权限。
6. 实际发言和任务结果再次成为事件；重要事件在空闲时做简短反思，供以后使用。

入口分别位于 `backend/run_api.py`、`backend/run_coordinator.py`、`backend/cognition.py`。这三层依次负责 HTTP/业务对接、执行调度、人物状态。

## 人物数据在哪里

业务数据库增加五张表，不增加新的数据库服务：

| 表 | 用途 |
| --- | --- |
| `mind_states` | 每个人物一份状态，以及单调递增版本 |
| `mind_experiences` | 原始观察、来源事件、个人反思处理状态、依赖来源 |
| `mind_receipts` | 已处理的“来源事件＋人物”标识 |
| `mind_cursors` | 运行事件消费到哪个序号 |
| `mind_outbox` | 已提交的人物变化通知，等待发往原运行事件流 |

角色与旧关系表继续保留。新关系不是把好感度每次机械加一，而是保存“哪个事件使我在什么领域形成何种判断”。领域信任与亲近程度不混为同一件事。初始关系分数是低置信度导入值，不是心理测量结果。

角色行为解释集中在 `backend/character_behavior.py`。目前涵盖能代、信浓、豪、埃佛森、雅努斯，注明来自本地角色材料的作者解释；没有把这些解释宣称为经官方核实的原作事实。用户编辑的人设优先。

## 两个数据库怎样保持一致

现有运行存储负责工具与任务事实，业务数据库负责人物状态。它们不使用跨库大事务。

消费一批运行事件时，在业务侧同一事务内写入经历、收件记录、状态和游标。如果事务失败，游标也不会前进，下次重新消费。

业务提交后，再把发件箱中的变化写回原运行事件流。如果写回后恰好崩溃，通知可能重复发送；通知保留稳定事件标识和人物状态版本，前端按版本读取，不能再次增加关系。

因此实现的是“允许投递重试，认知更新幂等”，而不是声称底层网络永不重复。

## 模型等待为什么不会锁住数据库

反思先取出普通字典并结束事务，再请求模型。返回后检查人物版本是否仍与请求时一致。

例如，人物在版本 10 开始反思，随后收到新要求，状态变成 11。版本 10 的反思不能覆盖 11；后续可针对最新状态重新处理。这称为乐观并发控制。

同一人物的工具操作与讨论可以并行，但两者共享相同状态。当前程序内同步数据库事务不跨 `await`；跨模型等待的更新使用条件版本提交。

## 哪些信息允许进入人物上下文

- 自己看到的用户要求和发言属于个人观察。
- 已参加任务的群聊与公开结果属于团队公共信息。
- 对别人的评价只保存在评价者自己的状态中。
- 反思中的推测不是客观事实，不能用来宣布工具成功。
- 朋友圈默认只获得“近期参与的任务已结束”一类粗粒度经历，不读取客户文件、路径或工作报告原文。

可见性过滤在检索之前执行，不能先混合全部记忆再要求模型自行保密。现有工具日志仍是团队执行证据，不是私人心理日志。

当前对他人的理解是有来源的短判断与合作倾向，不是完整的递归心智推理模型。

## 记忆怎样检索和纠正

检索限定为当前人物的未忘记经历，最多读取近期 100 条候选，再依据未兑现承诺、当前文本相关性及时间排序。最终最多八条摘要，使用保守字符估算控制约 2,000 token 的记忆预算。

这不是完整语义向量检索：很久以前又没有活跃承诺关联的经历，可能未进入候选窗口。后续可以增加持久化检索索引，但应保留同样的权限过滤和来源标识。

反思保存输入状态中引用的来源。用户纠正或忘记某条经历时，系统沿依赖关系排除后续判断，并清理相关关注点、承诺和情绪摘要。被排除的源不会因为重放旧事件而复活。

当前承诺只从人物自己的明确原话中提取；反思无法凭空添加未说过的承诺。自动判断兑现仍需保守处理，不能把“我会做”当作“已经做”。

## 讨论怎样帮助工作

执行成员仍可调用 `discuss`，提供目标成员和问题；支持建议、异议、答复、解决标记与续接线程。

每个任务最多八次讨论，同一问题最多两轮。真实工具失败可以触发一次自动求助，优先考虑人物已有的合作倾向。第二轮仍未解决时产生协调提示，完整讨论也进入后续审查上下文。

讨论没有工具权限，不是交付证据。任务依赖仍由原调度器校验，讨论不能直接替换其他成员正在运行的工作。成员可调整自己的执行方案；本轮没有开放任意动态改写整张依赖图。

普通聊天和定向讨论使用交互槽位；工具成员最多并行两个。后台反思、技能试用和社交受低优先级维护锁约束，前台工作到来会中断当前低优先级请求。

## 技能为什么不再“看一遍就学会”

合作候选来自可见的成功工具行为；不会照抄教师不可见的私人方法。当前提供两个可自动验收的任务族：目录清单、文件分类移动。

一个候选需要运行三个不同场景，每个场景分别使用原方法和新方法，共六次独立执行。场景包括中文名称、嵌套目录、空文件、多点文件名。

每次都通过真实工具网关操作独立目录；命令、浏览器、桌面等能力在试用中关闭。代码直接检查路径集合、文件哈希和清单 JSON，模型说“正确”不能替代检查。

六次都成功才自动启用，实际应用限定在对应任务族。暂停、超时、权限错误或场景不支持时，候选不晋升。缺少可靠验收器的 PDF 研究、编程、浏览器等候选继续保留，不能宣称已学会。

试用被前台任务打断后保留说明，下次创建新隔离目录。重启遇到 `testing` 状态会恢复为候选；不复用结果未知的旧试用目录。

任务审查发现与方法相关的修订问题时，学习方法可停用回退。网络失败本身不算方法退步。当前回退恢复先前可用方法选择，不是声称模型权重发生回滚。

## 公有方法怎样共享

通过试用的个人方法可以申请共享。秘书用无工具模型请求读取方法与试用证据，给出批准或拒绝理由。复核期间没有数据库写事务。

通过之后仍需用户点击“确认共享此方法”。共享记录保存方法内容哈希；方法改变后不能沿用旧批准。停用、回滚或撤回共享，会让后续公共方法选择停止应用该扩展。

人物学习、秘书审查与用户确认是产品机制，不是开发者修改代码时的额外审批规则。

## 配置与回退

| 环境变量 | 默认值 | 用途 |
| --- | --- | --- |
| `AZURJUUS_COGNITION_ENABLED` | `1` | 统一认知层；设为 0 使用原执行上下文 |
| `AZURJUUS_REFLECTION_ENABLED` | `1` | 空闲时进行简短模型反思 |
| `AZURJUUS_SKILL_TRIALS_ENABLED` | `1` | 空闲时安排技能试用和共享复核 |

反思默认 15 秒超时，最多重试一次；共享复核默认 30 秒超时。反思失败保留旧状态，不会撤回已经显示的回复。环境开关用于整体验证和回退，人物面板开关用于单个人物。

迁移先备份业务数据库、运行数据库和工作区配置，再增加表和版本。旧聊天、技能与关系保留；不根据旧任务补造人物的心理经历。

## 怎么判断完成了

程序验证检查权限边界、幂等、恢复、文件产物、接口和界面稳定性；人工验证检查自然度、角色辨识、关系合理性和成长连续性。

`tests/test_cognition.py` 覆盖关键状态行为。`tools/personality_benchmark.py` 准备 24 场景、四个提示条件、三次重复和 30 轮连续对话，并生成两份留空的人工评分表。

这个比较工具使用合成记忆，属于提示层实验，不能冒充完整生产系统的长期人格评价。批量云端评测目前尚未执行，人工胜出率未取得。现有 DeepSeek 文件任务和已运行界面回归仅证明对应链路可用。
